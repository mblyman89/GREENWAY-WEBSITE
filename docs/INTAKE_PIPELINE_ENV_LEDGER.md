# Intake Pipeline — Vercel Environment Ledger

> **Owner request (Round 5, verbatim):** "Will you add to the roadmap strategy to provide for me all of the vercel env variables to add to vercel at the very end of this whole pipeline build."

This is the one list of every environment variable the receiving-intake pipeline build (roadmap slices S00–S33) reads. **Each slice that adds or reads a variable adds a row here in the same PR.** `tests/compliance/intake-env-ledger.test.ts` fails the build if a pipeline flag in the code is missing from this ledger or from `.env.example`, or if a "shipped" row names a variable the code no longer reads.

**The final roadmap step (after S25)** is the **Vercel handoff**: the last PR of the build refreshes this file, and the owner gets the "Final Vercel checklist" at the bottom as a copy-paste list. Nothing in this pipeline needs a variable to be *set* to work. Every flag has a safe default when unset. So this list is about choosing values on purpose, not about fixing breakage.

How to set one in Vercel: Project → Settings → Environment Variables → add the name and value for **Production** (and Preview, if you test there) → **Redeploy**. Vercel only applies variables to new deployments.

## 5. `ATTACH_POLICY_RING` in plain English (what the "ring" is)

**The one-sentence version.** `ATTACH_POLICY_RING` is a volume knob for how much the AI lookup is allowed to do on its own. At `1` (today's setting, and what you get when it is unset) the AI only *suggests*; at `2` it may also *fill in* the facts it is at least 90% sure of, but only when a person presses **Save selected**.

**Why it is called a "ring".** The roadmap ships risky features in rings, like the rings of a target. You start in the small, safe centre and step outward only once you have seen it behave. Ring 0 is "off". Ring 1 is "watch only" (engineers call this *shadow mode*: the feature runs for real but its results are only shown and counted, never used). Rings 2 and 3 are "let it act". Nothing about the ring is a database setting. It is one Vercel variable, read on every request (`currentAttachPolicyRing()` in `src/lib/catalog/fact-attach-policy-server.ts`), so changing it and redeploying takes effect at once, and changing it back undoes it.

**What "attach" means.** When you press **AI Lookup** on a product, the AI searches the web and comes back with facts: a description, effects, aroma, flavor, strain type, and so on, each with a confidence score (for example "94% sure"). "Attaching" a fact means writing it onto the product's real records: the product record in the knowledge base (`kb_products`) and the strain library (`kb_strains`). Those are the records the menu and Product Enrichment read. A fact that is *not* attached goes to the **Enrichment suggestions** list instead, where a person accepts or rejects it.

**What each value does, step by step.**

| Value | Name | What happens when you press AI Lookup | What happens when you press Save selected | Footer counters on Product Onboarding |
|---|---|---|---|---|
| `0` (or `off`, `false`, `no`, `disabled`) | Off | The lookup shows what it found. No policy verdicts, no preview. | The save still works (through the S07 door): everything goes to Enrichment suggestions for a person. Nothing is attached automatically. | Hidden (and the page skips that read). |
| `1` (unset, empty, or anything unrecognised) | Shadow (watch only) | Each field gets a verdict and the panel shows a preview: "We found a description at 94% — would attach." Nothing is written by the lookup. | Every kept fact goes to Enrichment suggestions for your review. A brand-new strain is created **hidden** (not on the menu). **Nothing lands on a live record.** The receipt says "Saved for review". | Shown: "would attach N · pre-fill · suggest · left alone" over the last 30 days. This is the week of evidence the roadmap asks you to read before raising the ring. |
| `2` | Act | Same preview, worded "Auto-attach on Save selected (nothing saved yet)". The lookup itself still writes nothing. | Facts the policy says **attach** (90%+ and allowed for that field) are written to the product record and strain library, gap-fill only: a value a person already entered is never replaced. Everything else still goes to suggestions. The receipt lists exactly what landed where. With S11, the attached facts also appear on the onboarding row's Facts panel. | Shown, worded "ready to attach on save". |
| `3` | Act (default-on stage) | Same as `2` today. The bible reserves `3` for "this is now the normal behaviour", so the code treats `2` and `3` alike (`attachPolicyMode()` in `fact-attach-policy-core.ts`). | Same as `2`. | Same as `2`. |

**Which facts can ever attach on their own, even at ring 2.** The policy is per field (`FIELD_POLICY` in `src/lib/catalog/fact-attach-policy-core.ts`). Descriptive text (description, short description, summary, effects, aroma, flavor, terpenes, lineage) attaches at 90% or higher; 70–89% becomes a suggestion; under 70% is dropped. Strain type attaches only at 90%+ **and** when the strain library or the manifest agrees; otherwise it is pre-filled on the approve form for you to confirm. Category and type are never attached by a lookup: the approve form's own check decides them. Images, strain name, producer, ingredients and allergens are always suggestions, because a person must pick them (brand and legal reasons). A person's own answer always wins over the AI, and CCRS values from the state system are never rewritten.

**What the ring never does, at any value.** It never publishes anything to the website by itself (Approve with a price is still what puts a product live). It never runs a lookup on its own (a person always presses the button). It adds no background jobs, polls or crons. And a value it does not understand (a typo like `two`) falls back to `1`, the safe watch-only setting, so a typo can never switch on writing.

**What to do.** Leave it at `1` for now. Use AI Lookup on real deliveries for about a week, then read the footer line at the bottom of Product Onboarding ("Auto-attach preview (last 30 days, N lookups): would attach … · pre-fill … · suggest … · left alone …"). If what it *would* have attached looks right to you, set `ATTACH_POLICY_RING` = `2` in Vercel and redeploy. To undo, set it back to `1` (or `0`) and redeploy; nothing already saved is removed, and from then on saves go to suggestions again.
