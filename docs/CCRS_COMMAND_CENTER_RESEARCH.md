## 1. What CCRS is (and is not)

- CCRS = **Cannabis Central Reporting System**, the WSLCB traceability system.
- Submission is **manual CSV upload only** at `https://cannabisreporting.lcb.wa.gov/`,
  authenticated through **SecureAccess Washington (SAW)** (transitioning to WA.gov
  login by **October 2026**).
- **There is NO API.** No programmatic submission exists for licensees or integrators.
  The best a back office can do is: generate perfect CSVs, validate them, hand-hold the
  human through the manual upload, and track/verify completion.
- Errors from CCRS are returned **by email** to the account that uploaded the file.
- Integrators may upload on a licensee's behalf, but the **licensee remains ultimately
  responsible**. Only the license administrator can assign an integrator.
- There is no contingency email-submission path for reports; manifests must be
  generated by CCRS itself.

## 2. Reporting cadence and deadlines (deadline engine spec)

- **Reporting week = Sunday through Saturday.**
- Each week's activity is **due no later than the following Sunday** (i.e., activity for
  week ending Saturday `S` is due by end of Sunday `S+1`).
- Timezone context: CCRS filename timestamps are referenced in **PST**; operationally
  treat all deadlines as **America/Los_Angeles** (Pacific) wall time.
- More frequent reporting (daily, per-event) is **allowed and encouraged**.
- **If there is NOTHING new to report for a week, no upload is required.** There is no
  "no change" / null report mechanism. The command center must therefore distinguish
  "submitted" from "verified nothing-to-report" — both are valid week resolutions and
  both should be recorded in the submission ledger for audit defense.
- **Monthly (separate from CCRS):** the **LIQ-1295 Retailer Sales and Excise Tax
  report + payment** is due monthly **even with zero sales** (WAC 314-55-089(4));
  failure is grounds for suspension/revocation (WAC 314-55-092(2)). The back office
  already has an excise page (`/admin/reports/excise`); the command center must surface
  this monthly deadline alongside the weekly CCRS one.

## 3. Which CSVs a RETAILER must file (Table 1 of the guide)

Retailer-required upload types (only when there is unreported activity of that kind):

| CSV | When required (retailer) | Depends on |
| --- | --- | --- |
| `Strain` | New strain not already reported | — (Group 1) |
| `Area` | New/changed physical storage area | — (Group 1) |
| `Product` | New/changed distinct product | — (Group 1) |
| `Inventory` | New inventory or unreported changes | Strain, Area, Product (Group 2) |
| `InventoryTransfer` | Inventory **received** by the retailer | Inventory (both sides) (Group 3) |
| `InventoryAdjustment` | Any adjustment event | Inventory (Group 3) |
| `Sale` | Any sale activity | Inventory (Group 3) |

NOT retailer-required: `LabTest` (labs only), `Plant*` (producers), `Harvest.CSV`
(producers, added Oct 2025). `Manifest.CSV` (with new `LabtestexternalIdentifier`
column) is generated in CCRS for transport; retailers receive, they don't create it.

**Upload order dependency (10-minute rule):** referenced files must be submitted at
least **10 minutes before** dependent files. Order: Group 1 (Strain, Area, Product) →
Group 2 (Inventory) → Group 3 (InventoryTransfer, InventoryAdjustment, Sale).
Typical retailer receiving-day workflow per the guide: Product → Inventory →
InventoryTransfer.

## 4. File naming + header block (validation gate spec)

- **Filename:** `uploadtype_LicenseNumber_YYYYMMDDHHMMSS` — e.g.
  `sale_424683_20260125143000` (+ `.csv`). Timestamp referenced in **PST**.
  Upload types (as used in guide examples): `area`, `strain`, `product`, `inventory`,
  `inventoryAdjustment`, `inventoryTransfer`, `sale`.
- **File size:** ≤ 1 GB recommended (2 GB hard max).
- **Header block (first rows of every file):**
  - `SubmittedBy` — text (35).
  - `SubmittedDate` — `MM/DD/YYYY`.
  - `NumberRecords` — **must exactly match the data row count or the entire file
    fails.** This is a mandatory pre-upload validation gate.
- **Common data columns on most files:** `LicenseNumber` (numeric 6),
  `ExternalIdentifier` (text 100), `CreatedBy`, `CreatedDate`, `UpdatedBy`,
  `UpdatedDate`, `Operation` ∈ {`Insert`, `Update`, `Delete`}.
  Exception: **Strain has NO Operation/UpdatedBy/UpdatedDate columns** — strain rows
  are insert-only, can never be updated or deleted.

## 5. Per-file field specs (verified, retailer-relevant)

### 5.1 Area.CSV
- `LicenseNumber`; `Area` text(75) required IUD — errors: "Name is required", ">75 chars".
- `IsQuarantine` bool TRUE/FALSE required. **TRUE only applies to imported CBD**
  (quarantined until passing WAC 314-55-109 tests). Cannabis products: always FALSE.
- Plus ExternalIdentifier / CreatedBy / CreatedDate / UpdatedBy / UpdatedDate / Operation.

### 5.2 Strain.CSV (insert-only)
- `LicenseNumber`; `Strain` text(100) required, unique per license — cannot be
  "Unknown", "THC", or "Other". "Duplicate Strain" error means it already exists —
  **no corrective action required** (treat as benign in the error triage helper).
- `StrainType` text(50) required ∈ {`Indica`, `Sativa`, `Hybrid`}.
- Only `CreatedBy`/`CreatedDate`; NO Operation/Updated columns.
- Strain ≠ product trade name. For intermediate/end products use the primary strain
  source or "mix" as appropriate. If a strain already exists in CCRS, strain.CSV need
  not be re-submitted even though Inventory references it.

### 5.3 Product.CSV
- `LicenseNumber`; `InventoryCategory` text(50) required ∈ {`PropagationMaterial`,
  `HarvestedMaterial`, `IntermediateProduct`, `EndProduct`}.
- `InventoryType` text(50) required; valid values constrained by category (Table 2).
  Retail-relevant EndProduct types include: Cannabis Mix Infused, Cannabis Mix
  Packaged, Capsule, CO2 Concentrate, Concentrate for Inhalation, Ethanol Concentrate,
  Hydrocarbon Concentrate, Liquid Edible, Non-Solvent Based Concentrate, Sample Jar,
  Solid Edible, Suppository, Tincture, Topical Ointment, Transdermal,
  **Usable Cannabis**, Waste. IntermediateProduct includes Cannabis Mix, CBD, etc.
- `Name` text(75) required. `Description` text(250) — **required when InventoryType is
  Useable Cannabis or Cannabis Mix Packaged**, otherwise optional.
- `UnitWeightGrams` decimal(10,2) required — must be > 0 for Useable Cannabis /
  Cannabis Mix Packaged; other types may report 0. Error: "Invalid
  InventoryCategory/InventoryType combination" for bad pairs.
- Plus common columns incl. Operation.

### 5.4 Inventory.CSV
- Depends on Strain + Area + Product (≥10 min earlier).
- `LicenseNumber`; `Strain` text(100) must match a Strain.Strain **linked to this
  license** (error: "Strain Name reported is not linked to the license number");
  `Area` text(75) must match Area.Name; `Product` text(75) must match Product.Name
  **exactly as previously submitted (format and spelling)**.
- `InitialQuantity` decimal required, no negatives. `QuantityOnHand` decimal required,
  no negatives. `TotalCost` decimal required, **cannot equal zero** — used by LCB to
  detect below-cost sales (WAC 314-55-018 forbids discounting below acquisition cost).
  Trade samples: use $0.01 and include "Trade Sample" in name/description.
- `IsMedical` bool TRUE/FALSE required — **TRUE only when passing test results verify
  DOH medically-compliant status per WAC 314-55-102 & WAC 246-70-050.** This flag is
  one of the four legs of the medical excise exemption (see §7).
- Plus common columns incl. Operation.

### 5.5 InventoryAdjustment.CSV
- Depends on Inventory (with or prior).
- `LicenseNumber`; `InventoryExternalIdentifier` text(100) must match a previously
  uploaded Inventory.ExternalIdentifier **character-for-character**.
- `AdjustmentReason` text(50) required ∈ {`Destruction`, `Reconciliation`, `Lost`,
  `Seizure`, `Theft`, `Other`} (+ `ReturnedLabSample` per Table 3).
  Table 3 mapping: balance inventory→Reconciliation; theft→Theft; LCB seizure→Seizure;
  member left / self-sampling / budtender sample / vendor sample→Other; lab sample
  returned→ReturnedLabSample; destruction/disposal→Destruction; lost→Lost; daily
  waste→Other.
- `AdjustmentDetail` text(250) — **required when reason is Other or Theft**; details
  must say whether the adjustment adds or subtracts (quantity itself is always a
  **positive** decimal, no negatives).
- `AdjustmentDate` date `MM/DD/YYYY` required. Plus common columns incl. Operation.
- **Customer returns:** the guide/FAQ workflow is: Delete the sale row in a Sale.CSV
  (Operation=Delete on the identifiers) **and** report an InventoryAdjustment
  documenting the return with details.

### 5.6 InventoryTransfer.CSV (receipts)
- Required weekly for any facility that **receives** inventory. Depends on Inventory
  records existing for BOTH source and destination.
- `FromLicenseNumber` text(10) numeric, ≠ `ToLicenseNumber` text(10) numeric.
- `FromInventoryExternalIdentifier` text(100) must match the **seller's** reported
  inventory (seller must have filed their Sale.CSV/Inventory first — "Invalid
  FromInventoryExternalIdentifier" usually means the seller hasn't reported yet).
- `ToInventoryExternalIdentifier` text(100) must match the retailer's own
  Inventory.ExternalIdentifier (retailer must file Inventory.CSV first).
- `Quantity` decimal required, no negatives; unit of measure consistent with type.
- `TransferDate` date `MM/DD/YYYY`. Unique on Insert ("Duplicate InventoryTransfer for
  Licensee"). Plus common columns incl. Operation.

### 5.7 Sale.CSV (the big one)
- Depends on Inventory; inventory item must exist and **not be in quarantine**.
- Fields:
  - `LicenseNumber` numeric(6).
  - `InventoryExternalIdentifier` text(100) → prior Inventory upload.
  - `SaleType` ∈ {`RecreationalRetail`, `RecreationalMedical`, `Wholesale`}.
  - `SaleDate` `MM/DD/YYYY`.
  - `Quantity` decimal, no negatives.
  - `UnitPrice` decimal — **pre-tax**, no `$` symbols.
  - `Discount` decimal (retail only) — may not take price below acquisition cost
    (WAC 314-55-018).
  - `SalesTax` / `RetailSalesTax` decimal.
  - `CannabisExciseTax` (a.k.a. `OtherTax`) — **required for all retail sales; must
    equal 37% of unit price EXCEPT medical: "Only Medical Sales can be 0."**
  - `SaleExternalIdentifier` text(100) + `SaleDetailExternalIdentifier` text(100) —
    both unique on Insert. Rows sharing a `SaleExternalIdentifier` (one ticket, many
    lines) must share SaleType + SaleDate and have unique detail identifiers, else
    "Duplicate Sale for Licensee".
  - Plus common columns incl. Operation.
- **Returns:** delete the sale identifiers + file an InventoryAdjustment (see 5.5).

## 6. Error handling workflow (triage helper spec)

1. CCRS emails errors to the uploader's email account.
2. Fix by adjusting the ORIGINAL file per the Upload User Guide and re-uploading
   (corrections reference the same external identifiers; `NumberRecords` must again
   match).
3. Benign error: "Duplicate Strain/StrainType" → no action needed.
4. If unresolvable: email **examiner@lcb.wa.gov** attaching the CSV **and forwarding
   the CCRS error email**. The command center should generate this email as a DRAFT
   (mailto/EML) that the owner reviews and sends — never auto-send (drafts-only rule).
5. Contacts: servicedesk@lcb.wa.gov / 360-664-1776 (technical/SAW),
   examiner@lcb.wa.gov (traceability data), cannabistaxes@lcb.wa.gov / 360-664-1789
   (LIQ-1295/tax), cannabisenf@lcb.wa.gov (enforcement/compliance),
   cannabisendorsement@lcb.wa.gov (medical endorsement).

## 7. DOH / medical sales (medical section spec)

Medical **excise + sales tax exemption** (in effect since June 6, 2024; RCW 69.50.535,
RCW 82.08.9998, WAC 246-70) requires **ALL FOUR** conditions:
1. Store holds a **DOH Medical Endorsement**.
2. Customer is a **qualifying patient/designated provider registered in the DOH
   Medical Cannabis Authorization Database with a valid recognition card** — the
   database must be checked **EVERY transaction** (status can change even if the card
   looks valid).
3. Product was reported **`IsMedical=TRUE`** ("Medically Compliant") in the retailer's
   Inventory.CSV (only lawful with passing DOH-compliant test results,
   WAC 314-55-102 / WAC 246-70-050).
4. Sale reported in Sale.CSV as **`SaleType=RecreationalMedical`** with **both tax
   columns $0.00**.

Additional exemption rules (March 2026 LCB bulletin):
- **CHABA products** (cannabis health and beauty aids): sales + excise exempt.
- **High-CBD compliant products** (DOH-identified): **sales-tax** exempt to ANY customer.
- The exemption is **NOT a discount** — never model it as one; it is mandatory when
  conditions are met and applies to both sales tax and excise tax.

Endorsement duties (recordkeeping the command center should checklist):
- Train all employees on medical cannabis / card recognition (RCW 69.50.375,
  WAC 314-55-080) — must have a certified medical cannabis consultant on staff.
- Enter qualifying patients/designated providers into the DOH database; issue
  DOH-compliant recognition cards; retain card + transaction records per DOH/DOR.
- There is **no separate DOH report upload** for retailers — DOH obligations manifest
  through: DOH database entry/check at point of sale, `IsMedical` flag in
  Inventory.CSV, `RecreationalMedical` SaleType + $0 taxes in Sale.CSV, and the
  medical-exempt lines on the monthly LIQ-1295. The command center's "DOH / Medical"
  panel = those four checkpoints + endorsement duty checklist.

## 9. Command Center build blueprint (design targets)

1. **Deadline engine (pure core):** week = Sun–Sat Pacific; due next Sunday; status
   per week ∈ {upcoming, due_soon, due_today, overdue, submitted, nothing_to_report};
   monthly LIQ-1295 deadline surfaced side-by-side.
2. **Hand-held weekly wizard:** step-by-step — (1) pick week → (2) review activity
   detected (sales, adjustments, transfers received, new products/strains/areas) →
   (3) generate CSVs in dependency order with correct filenames → (4) pre-flight
   validation gates → (5) guided manual upload to CCRS (open portal, ordered
   checklist, 10-minute dependency timer guidance) → (6) record submission in ledger
   → (7) watch for error emails, triage helper.
3. **Validation gates (pure core):** filename regex + PST timestamp; header
   NumberRecords == rows; per-field length/enum/format checks per §5; 37% excise
   check with medical-$0 exception; no negatives; TotalCost ≠ 0; duplicate
   SaleExternalIdentifier/detail detection; dependency-order warnings; below-cost
   discount warning (WAC 314-55-018).
4. **Submission ledger (Supabase, migration drafted for manual apply):** one row per
   week per upload type: generated_at, filename, record_count, submitted flag,
   submitted_at, submitted_by, nothing_to_report flag, error status, notes.
5. **Reminders/notifications:** email reminders + (if infra exists) push; cadence
   e.g. Thursday heads-up, Saturday close-of-week, Sunday due-today, Monday OVERDUE
   escalation; LIQ-1295 monthly reminders. Verify existing notification/email infra
   before building (W-1).
6. **Error triage helper:** paste CCRS error email → classify (benign duplicate-strain
   vs actionable) → guided fix → draft email to examiner@lcb.wa.gov (draft only).
7. **DOH / Medical panel:** four-leg exemption checklist, endorsement duty checklist,
   medical sale count for the week, IsMedical inventory flag audit.
8. **AI assistance:** drafts-only explanations of errors, field help, "what do I owe
   this week" summaries. Never auto-submit anything.
